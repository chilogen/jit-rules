# Isolated launch (harness lane, after installers)

**Read first**: the "Isolated launch" section of spec/harness.md and the launcher section of spec/contracts.md.

**Change only**: `internal/launcher/` (including the four implementations), `internal/cli/isolate.go`.

## Steps

1. `internal/launcher`: registry, `MergeArgs`.
2. Four implementations: `claudesettings`, `codexconfig`, `dshpatch`, `manual`. Hook entries come from `harness.HookEntries`.
3. CLI: `jitr isolate`.

## Required tests (Prepare only generates content and never launches a real harness)

- claude-code with user arguments `["-p", "hi"]`: Args equals `["--setting-sources", "", "--disable-slash-commands", "--settings", <tmp>/settings.json, "-p", "hi"]`; settings.json has `"autoMemoryEnabled": false` and hooks for 4 events; with `--no-jitr`, settings.json has no `hooks` key.
- codex with user arguments `["exec", "hi"]`: Args starts with `exec`, followed by the definition's args, then `--ignore-user-config`, then 8 `-c hooks...` arguments (4 events, two arguments each, sorted by event name), and finally `hi`.
- codex: with `CODEX_HOME` set to a temporary directory containing `auth.json`, `hooks.json`, and `config.toml` → `Launch.Env["CODEX_HOME"]` is `<TempDir>/home`, which contains only `auth.json`, with the same content and permissions as the original; the same with `--no-jitr`. When the directory `CODEX_HOME` points to has no `auth.json`, `<TempDir>/home` is empty and Prepare does not fail.
- codex with user arguments `["hi"]` (interactive mode): the isolation arguments come first, and there is **no** `--ignore-user-config`.
- codex: with `{bin}` set to `C:\Users\a b\jitr.exe` and `Request.GOOS` `windows`, the generated TOML values exactly match hand-written expected strings (the `\` in the path and the `"` in the command are both escaped correctly).
- deepseek: `$DSH_HOME/cordis.patch.yml` inserts `memory-engram`, `profiles/web/cordis.patch.yml` inserts `memory-x`, and there is also an `other` → the generated patch disables the 4 fixed ids plus `memory-engram` and `memory-x`, does not disable `other`, and its last item is the insert of the hooks bridge; with `--no-jitr`, that item is absent and there is no hooks.json.
- trae (manual): `jitr isolate trae --` exits with 1 and prints the notes.
- `jitr isolate claude-code --json -- -p hi`: exit code 1, stdout is a JSON object with `ok` false, and no child process is started (as in the exit-code test below, override program with a script that writes a marker file, and check the marker does not exist).
- After `jitr isolate`, the temporary directory has been deleted; its exit code equals the child's (in the test, override claude-code with a definition in the user directory whose program is a script generated by the test that exits with 7; skip on Windows).
- The child's environment has `JITR_ISOLATED=1` and the variables from `Launch.Env` (in the test, have the Launcher return `{"X_TEST": "1"}` and check the child sees `X_TEST=1`); with `--no-jitr` it also has `JITR_DISABLE=1` (check with a script that writes its environment to a file).

## Done when

`make check` passes. Commit `isolated launch`.
